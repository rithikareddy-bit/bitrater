## 2. What "token" means here — grounded spec (do not deviate)

Source: <https://docs.cloud.google.com/media-cdn/docs/generate-tokens> (Google's `sign_token` code).

- Token = `key=value` fields **joined by `~`**, placed in **one** query parameter.
- **Field order** (top-to-bottom in `sign_token`): `<path-field>`, `Starts`, `Expires`,
  `SessionID`, `Data`, `Headers`, `IPRanges`, then `Signature` **last**.
- **`FullPath` is special:** the token string contains the **literal marker** `FullPath` (the path
  is NOT duplicated in the token), but the **signature is computed over** `FullPath=<path>`.
  Verbatim from Google's code:
  ```python
  tokens.append("FullPath")
  to_sign.append(f"FullPath={full_path}")
  ```
- `Expires=<int unix seconds>` — present in both the token and the signed value.
- **Ed25519** signature over the UTF-8 of the `~`-joined `to_sign`; encoded **web-safe base64,
  padding stripped** (our existing `_b64url` already does exactly this).
- **No `KeyName`** in a token (unlike our signature format). The keyset is identified by the CDN
  route (`signedRequestKeyset`), not by the token.
- `FullPath` (path only, from the first `/`, no scheme/host/query) — e.g.
  `/19438a40-…/15062026_150246/oh-my-dog_ep_1_…_combined.m3u8`.

**Our token (master-only, single-token) will be:**
```
to_sign     = "FullPath=/<path>~Expires=<unix>"
signature   = ed25519_sign(to_sign)            # then web-safe base64, unpadded
token       = "FullPath~Expires=<unix>~Signature=<sig>"
final URL   = "<master url>?<TOKEN_PARAM>=<token>"
```

- TTL stays **10h**, rotation stays **2h** (same clocks as today).
- Keyset stays `chaishots-playback-keyset` (same Ed25519 key — no new key).

### Step 1 = the entry token on masters (shared foundation of dual-token)
This document's phases generate **one token on each master only** — the **entry token**. We never
generate tokens for children/segments (that would be baking = the old breakage). In the final
**dual-token** state, the children's/segments' tokens are minted and injected by the **CDN**
(propagation), not by us. So:
- Step 1 (this doc): our Lambda tokens **all masters** in Mongo. ✅ shared by master-only *and* dual-token.
- To reach **full dual-token** (segments protected): a **follow-on phase** configures CDN
  `PROPAGATE_TOKEN_HLS_COOKIELESS` so the edge injects segment tokens. **Not in this doc's phases yet** —
  it carries a **caching question** (manifest rewriting) that must be **measured on the canary first**.
- **Decision after step 1:** either (a) stop at **master-only** enforcement (caching untouched, segments
  open) as an interim, or (b) go straight to **dual-token propagation** (segments protected, pending the
  caching measurement). Step 1 does not commit you to either — that's its value.
- Note: with dual-token propagation you enforce *everything*, so the "legacy must become combined" gap
  from master-only **may not apply** (Path B) — see the enforcement-pattern note below.

### Dual-token enforcement pattern — enforce on `.m3u8` (all), not `_combined.m3u8`

For the **final dual-token** state, enforce on **all `.m3u8`** (masters + child playlists) + segments —
NOT just `_combined.m3u8`. Because propagation injects tokens into the children, master-vs-child no
longer needs to be pattern-separable, so the `_combined` suffix is unnecessary. **Consequence: legacy
`/hls/` masters (also `.m3u8`) get covered WITHOUT migrating them to combined** — this is Path B's whole
appeal.

Two conditions for a legacy URL to actually *survive* (not 403) under `.m3u8` enforcement:
1. **Also generate entry tokens for the legacy masters in Mongo.** Today the sweep only tokens
   `_combined.m3u8` (the `COMBINED_MARKER` filter in `resign_playback_urls.py`). Widen generation to
   include the legacy `/hls/` playback URLs too — otherwise an *enforced-but-untokened* legacy master
   returns 403 (breaks, not survives).
2. **Measure caching under propagation first** — the one open risk (propagation rewrites manifests).

So the dual-token switch = (a) widen token generation beyond `_combined` to **all** masters (combined +
legacy), (b) change the enforce pattern from `_combined.m3u8` → `.m3u8`, (c) add CDN propagation,
(d) **gated on the caching measurement**. It removes the combined-migration requirement entirely.

Step 1 (today) — tokening the combined masters — remains the correct foundation; the dual-token move
just widens generation to legacy and swaps the enforce pattern.
